思考强度（全局）

作用于网关对 reasoning_effort 的注入与改写；改动立即生效，并在网关配置了 LMR_CONFIG_FILE 时落盘（重启自动恢复，见上方状态条「持久化」）。 单个模型的默认强度与专属映射请在下方「模型配置」里按卡定制。

默认思考强度
请求未带 reasoning_effort 时注入该值；「跟随后端默认 (null)」表示网关不注入。
思考强度映射
命中映射的请求会把 reasoning_effort 改写为新值，例如 high→xhigh。to 留空的行提交时忽略； 删除一行后直接「保存映射」即可移除该映射（保存提交的是完整列表）。

模型配置

每个模型一张卡：上下文长度、默认思考强度、该模型专属强度映射、能力启用。 同名模型跨多个 provider 会合并成一条（来源列显示所有端口）。

添加自定义模型
后端不支持每模型配置（GET ./config 无 models 字段），请升级 llm-router。

虚拟模型映射

虚拟模型是对外主入口，与真实模型并存、一起出现在 /v1/models； 一个别名 1 对多地映射一组实际模型（targets），由路由策略在这一组里选落点。 组里的模型都不在线时，请求会得到「无可用 worker」。旧形状的单值 target 仍是合法的 代表值（只配一个模型时填它即可，两者都缺省时由候选绑定推断）。每行还可选候选实例白名单 （只把该别名限定到勾选的实例）与 context_window 覆盖（留空=不覆盖）。 虚拟模型这一层只允许配 context-window 覆盖：调度策略请在「路由策略」页配， 思考强度请在对应的模型卡片上配。

保存提交的是完整列表：删除一行后直接「保存映射」即可移除该别名。 整行留空的行提交时忽略；别名留空、模型组与代表值都缺省、别名等于自身任一 target、别名指向另一个 别名、候选绑定的模型不在模型组里等非法行由后端整体拒绝并给出原因（本页会先给一遍中文提示）。 候选实例一个都不勾 = 全池可选；上下文留空 = 不覆盖。旧后端只认 {model,target}，多出的字段会被忽略。
后端不支持虚拟模型映射（GET ./config 无 virtual_models 字段），请升级 llm-router。

模型名映射

环境默认值（只读）

运行时改动重启后回到环境默认；改名由 watcher ledger 持久化。

配置 JSON（源码编辑）

这份 JSON 等价于容器环境变量（LMR_DEFAULT_EFFORT / LMR_EFFORT_MAP / LMR_MODEL_CTX / LMR_MODEL_EFFORT / LMR_MODEL_EFFORT_MAP / LMR_MODEL_MODALITIES / LMR_VIRTUAL_MODELS），可以先导出再粘进 compose 固化。 「校验并应用」走 POST ./config/apply 整体替换：缺省字段视为清空； model_map 会转发 llm-watcher 落地改名。任一字段非法整体拒绝，不产生半提交。

virtual_models 是对外主入口：一行 model（别名）用 targets 映射一组实际模型名，可带 workers（规范化 url 白名单）与 context_window（正整数，该入口唯一允许的覆盖，网关据此钳制下游的 max_tokens / max_completion_tokens；不想要覆盖就整个键删掉，写 null 或空数组会被 旧 build 误判）。target 是旧形状的代表值，写了 targets 时可省；两者都缺省时 由 candidates 的模型名推断。调度策略与思考强度不在这里配（分别在路由策略页、模型卡片）。 本视图无损读写：读到的 candidates 与任何未识别的键都会原样写回，缺省的可选字段则 整体缺席。upstreams 的 api_key 回显恒 null（脱敏）： 提交时保持 null 或删掉该键 = 不动已存密钥，填 "" = 清除，填值 = 设置。
