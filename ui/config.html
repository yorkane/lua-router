思考强度（全局）

作用于网关对 reasoning_effort 的注入与改写；改动立即生效，并在网关配置了 LMR_CONFIG_FILE 时落盘（重启自动恢复，见上方状态条「持久化」）。 单个模型的默认强度与专属映射请在下方「模型配置」里按卡定制。

默认思考强度
请求未带 reasoning_effort 时注入该值；「跟随后端默认 (null)」表示网关不注入。
思考强度映射
命中映射的请求会把 reasoning_effort 改写为新值，例如 high→xhigh。to 留空的行提交时忽略； 删除一行后直接「保存映射」即可移除该映射（保存提交的是完整列表）。

模型配置

每个模型一张卡：上下文长度、默认思考强度、该模型专属强度映射、能力启用。 同名模型跨多个 provider 会合并成一条（来源列显示所有端口）。

添加自定义模型
后端不支持每模型配置（GET ./config 无 models 字段），请升级 llm-router。

虚拟模型映射

虚拟模型是对外别名，与真实模型并存、一起出现在 /v1/models； 请求用别名会被路由到 target 指向的上游模型。target 不存在时，请求会得到「无可用 worker」。

保存提交的是完整列表：删除一行后直接「保存映射」即可移除该别名。 两侧都留空的行提交时忽略；别名留空、目标留空、别名等于目标等非法行由后端整体拒绝并给出原因。
后端不支持虚拟模型映射（GET ./config 无 virtual_models 字段），请升级 llm-router。

模型名映射

把上游原始模型名改写为对外名称；每行一条，「新名」留空的行视为删除该条目。

环境默认值（只读）

运行时改动重启后回到环境默认；改名由 watcher ledger 持久化。

配置 JSON（源码编辑）

这份 JSON 等价于容器环境变量（LMR_DEFAULT_EFFORT / LMR_EFFORT_MAP / LMR_MODEL_CTX / LMR_MODEL_EFFORT / LMR_MODEL_EFFORT_MAP / LMR_MODEL_MODALITIES / LMR_VIRTUAL_MODELS），可以先导出再粘进 compose 固化。 「校验并应用」走 POST ./config/apply 整体替换：缺省字段视为清空； model_map 会转发 llm-watcher 落地改名。任一字段非法整体拒绝，不产生半提交。

解析失败不发请求；应用成功后表单视图同步刷新。
